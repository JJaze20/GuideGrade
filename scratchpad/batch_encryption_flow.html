GuideGrade · Security Model

How the app keeps examinee data secure

Two independent layers, both fully offline-capable: a device fingerprint/PIN gate on every open, and BatchCryptoService encrypting every batch at rest with AES‑256‑GCM — a key held in the platform's own secure hardware, not in a file next to the data it protects.

Getting into the app

Every cold start or return from the background, before any screen renders.

Every file, at rest

What actually happens to a batch's data and photos on disk, independent of whether the app is open.

Protects against
  • Someone reading the raw files directly — a rooted device, an ADB pull, physical extraction. Without the Keystore-backed key, the bytes are unreadable ciphertext.
  • An unattended phone that's still signed in — the lock gate re-checks the person holding it, every open, closing what used to be an open gap.
Does not protect against
  • The very first sign-in on a device, which still needs a real network connection to authenticate.
  • The Supabase cloud-sync upload — a separate, already-secured plaintext-over-TLS channel.
  • The device's own lock method being defeated — the app trusts whatever fingerprint/PIN the phone itself already trusts.
